This repository contains the code used for all experiments conducted in the paper 
**Investigating the Role of Reasoning-Language Alignment in Monolingual Retrieval-Augmented Generation**.

As the source material that was used for the evaluation (i.e. region description books from the german RPG *The Dark Eye*) we performed is copyrighted, 
we cannot publish it with this repo. We do however publish the tools that were developed and used to extract the dataset from the pdf versions of the books, 
so that anyone with access to the pdfs can reproduce our study.

The code in this repository is structured into two folders: 

- Scripts: all scripts that were used to create the dataset(s) and extra content (e.g. graphs), as well as to evalute the results using an LLM as a judge approach
- Experiment tools: contains the code to run the RAG chatbot tool and to process a dataset with it

### Processing the pdfs

0. To reproduce the exact results shown in paper, you will need the pdfs of the region description books G01, G05 and G08 from the fourth edition of *The Dark Eye*.
1. *pdf_to_xml.py* can be used, to convert the pdf files to xml in the *alto* format, using the tool *pdfalto*
   - You will likely need to first compile [pdfalto](https://github.com/kermitt2/pdfalto) yourself for this step. Follow the instructions in the [README](https://github.com/kermitt2/pdfalto).
   - During our experiments, we encountered the issue that the xml files generated by pdfalto missed some words that were existing in the pdf books. The debug output of pdfalto listed them however.
     To counter this, we capture the wordstream of the debug output in this step and save it as well, it will be later used to restore the lost fragments of the text
2. Use the *xml_to_yaml.py* script, to convert the xml alto data into a simpler yaml file
   - The bounding box information contained in the alto file is used to sort the text sections into the correct reading order here. As this automatic process is error prone, the order will be needed to be fixed with human assistance 
   - to fix wrapped wo-rds, this script also generates a *wordcounts* dictionary, that will later be used to correct the spelling of words that stretched over multiple lines in the source material
   - Different fonts used in the pdf are mapped to markdown representations in this step 
3. Next, we need to use *scatter_pdf_marker.py* to convert each page of the pdf source into a single markdown file
   - Marker is a pdf to markdown conversion tool. The reason we do not use it as our main tool is, that it does not get the text order correct in many cases and after the conversion to one markdown file it is hardly possible to fix the ordering 
   - We will need the markdown pages in the next step
4. Now for the most complex/time-consuming step: *data_processing_and_fixing*
   - As mentioned before, there are two main issues with our extracted data
       1. Some words may be missing
       2. The text order might be messed up in some cases
   - First, we address the missing words problem. There are two cases that we need to consider.
     - If there are just some words missing anywhere on the page, we can reconstruct them by comparing the text block content in our datastructure with the best matching slice of the word stream from pdfalto's debug output captured in step 1.
       - This process usually happens automatically. Only if the detected difference is very large, the user is prompted for confirmation to prevent text blocks being messed up by false matches.
     - If the missing words are part of a headline (or a complete headline is missing), this is a more complex case. The alto debug output does not contain any style information.
       Therefore, we compare the headlines found in the *marker* output with the ones we find in our yaml data from step 2. If there are additional headlines found, the tool will try to add them
       - As the headline levels are very important to construct a sensible RAG dataset later, and Marker does not get the levels correct in many cases, the user will often be prompted to verify/correct the found headlines and their levels via a simple terminal interface
       - To simplify the decision, the script tries to open the relevant pdf page in a pdf viewer (*okular*, you may want to adapt this in *utility.py* if you prefer to use a different pdf viewer) to show the user how the original correct headlines 
   - The second problem is a bit harder to address, as there is no simple way to order the text automatically in a way that is always correct
     - Therefore, the user will be presented with a CLI, designed to enable them to easily and intuitively move around text blocks and fix their order
     - Additionally, the script also tries to open the relevant part of the pdf in okular again, to assist the user during the reordering
     - The CLI allows to save intermediate results. It can be re-invoked later to start sorting exactly were you stopped before.
5. The last step is easy again: the corrected yaml data is loaded into a custom data structure called *BookData*, which is later used for the experiments. This can be done via the script *information_container.py*


## Evaluating the dataset

The main RAG tool was once planned to be included in a series of tools with backend and frontend parts, therefore the folder structure is still splitted.
For evaluation however, you only need the backend part.

To start the evaluation for a RAG dataset via

```
backend/main.py --eval-meisterwissen --meisterwissen-experiment RAG 
```

To evaluate the system on a QA dataset without giving it access to a RAG knowledge base, you can use


```
backend/main.py --eval-meisterwissen --meisterwissen-experiment NO_RAG 
```
